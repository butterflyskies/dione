# Typed Teams scoped identities

Six distinct private types carry tenant, application, bot, actor, conversation, and activity coordinates through production configuration, authenticated ingress, authority storage, resident events, deduplication, and reply receipts. All constructors and deserializers preserve exact spelling and validate nonempty values of at most 512 UTF-8 bytes without control characters. Application IDs additionally gain validation at configuration and stored-authority boundaries. Syntax does not grant authority; existing JWT, tenant, channel, service-origin, and current-policy checks remain required.

The authority-store schema remains version 1, and the Codex provider-key representation remains tagged Teams JSON with the same four independent scope fields. Literal prior authority and inbox fixtures retain exact JSON equality. Malformed stored coordinates fail before authority exposure without rewriting files. Real restart/dedup coverage changes tenant, bot, conversation, and activity independently, pairing acceptance with same-scope duplicate rejection. The actual TLS bridge fixture pairs a valid reply receipt with HTTP 200 plus an invalid outgoing ID, requiring an uncertain outcome, consumed durable authority, and no second token request or POST.
